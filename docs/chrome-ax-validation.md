# Chrome 辅助功能声音标记：验证记录

日期：2026-10-29（本机 Asia/Taipei）。

## 验证环境与范围

- macOS 26.7，Apple Silicon，日常正在运行的 Google Chrome 主进程。
- Chrome 运行实例加载的 Framework 为 155.0.8059.80，界面音频标记为英文。
- 没有安装 Chrome 扩展、开启远程调试、修改系统音量、读取 Cookie，
  也没有执行网页中的 AppleScript JavaScript。
- 为专用测试页添加了标签；现有网页不导航、不暂停、不关闭。
- 原型先验证，关键条件通过后才接入生产扫描器。

## 实测结果

| 条件 | 实测证据 | 结论 |
| --- | --- | --- |
| 直接读取原生标签栏 | 原型读取 88 个既有原生标签控件，跳过 AXWebArea 和 AXToolbar | 不依赖扩展可读取标签控件 |
| 极低信号 -80 dBFS | Core Audio 输出流活跃，但 Chrome 未添加 Audio playing | 不能用任意静默/过低信号代替发声标记验证 |
| 测试页 -60 dBFS 非零信号 | `SoundFinder AX 验证 - Audio playing - Memory usage - 79.5 MB` | Chrome 发声标记可被原生 AX 接口读到 |
| 后台标签页 | 打开另一专用测试页，原页 AXValue 为 0，仍有 Audio playing | 普通后台标签页可检测 |
| 标签页跳转 | AXPress 后重新读取：测试页 AXValue 从 0 变为 1，后台验证页变为 0 | 原生标签页选择可行，不需新开网页 |
| 全零静默输出 | 页面状态为“全零静默输出”，短暂延迟后标签只剩标题和内存标记 | 正确区分输出流活跃与 Chrome 发声标记 |
| 停止测试音 | 页面状态为“已停止”，辅助功能标签没有 Audio playing | 停止状态可观察 |
| 生产扫描器 | `soundfinder chrome-list` 读取 91 个原生标签控件，warnings 为空 | 接入后原生遍历工作正常 |
| 已静音标记 | 生产扫描器读取到了既有原生标签的 `Audio muted` 后缀 | 已静音可以单独分类；没有修改原网页静音设置 |

数值是不同时间点的快照，标签数量可能随用户正常操作改变，不作为全局完整性证明。
AXPress 仅在专用测试标签上执行；之后观察到用户在其他网页工作，停止进一步焦点操作。
测试音已停止。专用测试标签页仍保留，用户可自行关闭。

## 自动测试

接入时 12 项 Swift 单元测试通过，覆盖：

- 音频状态后缀与内存后缀解析；
- 非发声名称不误作为声音标记；
- 跳转参数的编码、验证与无效参数拒绝；
- 无 Core Audio 来源时仍保留 Chrome 标签结果；
- 无权限提示及应用级兜底；
- 标签标题筛选与部分结果警告；
- 原有进程归属、浏览器 Helper 合并、PID/设备筛选等 7 项测试。

单元测试不替代 Alfred 环境中辅助功能授权和完整快捷键交互验证。

## 接入决策与限制

普通前台/后台标签页的“读取标记 + 选中原标签”条件已通过，因此纳入 v1.1.0，
可在工作流配置中关闭，保留 v1.0 安装包回退。

尚未完整验证折叠/隐藏/最小化窗口、多配置文件、所有 Chrome 音频机制、
非英文界面以及 Alfred 发起的完整 UI 链路。当前不声称在所有这些场景可靠。
已静音字段只验证了现存标记读取，没有为了测试去切换用户网页的静音状态。
标签栏结构或状态变化时拒绝跳转，保留刷新提示与原有应用级结果。
